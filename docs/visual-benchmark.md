# InBot — Visual Benchmark

> Este documento analisa as três referências visuais definidas para o projeto.
> **Nenhum layout, texto, componente ou asset deve ser copiado diretamente.**
> O objetivo é capturar princípios: ritmo, hierarquia, acabamento, espaçamento e narrativa.

---

## Peso das Referências

| Referência | Papel | Peso |
|------------|-------|------|

## 01 — Sqala Tech (Referência Principal)

**URL:** https://www.sqala.tech/pt-BR

### O que observar

- Arquitetura de seções modular e progressiva
- Uso de cores vibrantes como acento em fundo neutro
- Cards com bordas suaves e espaçamento interno consistente
- Microinterações sutis (elementos orbitais, sliders de comparação)
- Tom assertivo e de negócios: "Você nem vai lembrar das outras"
- Métricas visíveis como prova de escala
- Alternância entre seções densas e mais abertas

### O que pode inspirar (princípios)

- **Progressão narrativa:** cada seção avança a conversa com o usuário
- **Hierarquia visual clara:** badge → headline → subtext → CTA
- **Glows e blur SVG** como textura de fundo — profundidade sem peso
- **Cards funcionais** com ícone, título, descrição curta
- **Sliders de comparação** para mostrar o antes/depois de uma solução
- **Métricas em destaque** para construir credibilidade com números
- **FAQ** para reduzir fricção na conversão

### O que NÃO copiar

- A paleta de cores específica (amarelo + azul dela)
- Os ícones e ilustrações proprietários
- O layout de grid exato das seções
- Qualquer texto ou microcopy
- A comparação "com Sqala vs. sem Sqala" (é de marca deles)

### Como adaptar para InBot

- Manter a progressão narrativa mas com a paleta Aurora/Núcleo/Nebulosa
- Usar glows radiais azuis no lugar dos blurs pastéis
- Adaptar a estrutura de cards para comunicar agentes, canais, jornadas
- Criar métricas que representem a escala real da InBot
- Usar bordas sutis em nebulosa em vez das bordas brancas/claras da Sqala

## 02 — Apple (Clareza e Acabamento)

**URL:** https://www.apple.com/

### O que observar

- Whitespace extremamente generoso — cada produto tem seu próprio espaço
- Cada hero section comunica uma coisa só
- Copy mínimo: 3–8 palavras no headline, 1 frase no subtext
- Imagens do produto falam mais que o texto
- Hierarquia tipográfica perfeita sem ruído visual
- Navegação limpa, sem sobrecarga de links
- Preto e branco como base — a cor está no produto

### O que pode inspirar (princípios)

- **Uma mensagem por seção:** não tentar dizer tudo de uma vez
- **Respiro como elemento de design:** o espaço vazio não é desperdício, é intenção
- **Typografia como elemento central** — o texto é o design
- **Confiança sem exclamações:** não precisar gritar para comunicar valor
- **CTA direto:** "Compre" ou "Saiba mais" — sem verbo fraco
- **Ritmo de scroll:** o usuário desce e encontra uma revelação por vez

### O que NÃO copiar

- O uso de produtos físicos como ponto focal (InBot é software)
- Imagens com fundo branco puro (não combina com a identidade InBot)
- O modelo de grid ultra-simétrico da Apple (pode parecer genérico)
- O modelo de precificação no footer (contexto diferente)

### Como adaptar para InBot

- Aplicar a filosofia "uma mensagem por seção" em cada bloco da landing
- Usar respiro generoso entre os cards e seções
- Manter headlines curtos e precisos (evitar headlines de 3 linhas)
- Deixar os dados e números do produto "respirarem" sem competição visual
- Tratar a navegação como elemento de confiança, não de volume

## 03 — Insany (Presença Digital e Ritmo)

**URL:** https://insany.com.br/

### O que observar

- Ritmo claro entre seções: alternância de densidade
- Numeração sequencial (001, 002...) como elemento de organização
- Seção de portfólio que mostra trabalho real antes de descrever serviços
- Proposta de valor direta: "Design e tecnologia que despertam desejo"
- Métricas de presença: anos de atuação, projetos, clientes
- Posicionamento de parceria, não transação
- Seção de metodologia que legitima o processo

### O que pode inspirar (princípios)

- **Mostrar antes de descrever:** o trabalho (ou produto) fala primeiro
- **Métricas de legitimidade:** anos, projetos, clientes — constroem confiança
- **Ritmo alternado:** seção densa → seção aberta → seção densa
- **Posicionamento de parceria:** "somos seu time", não "somos um vendor"
- **Numeração como âncora visual:** organiza sem precisar de título grande
- **Evidências concretas:** depoimentos, números, cases reais

### O que NÃO copiar

- A estrutura de portfólio de agência (InBot é produto, não serviço)
- A numeração sequencial como recurso de design (risco de parecer imitação)
- Os serviços listados (contexto completamente diferente)
- Tom de agência criativa (InBot tem tom mais institucional/tecnológico)

### Como adaptar para InBot

- Adaptar o ritmo de alternância para as seções da landing InBot
- Usar métricas de produto como legitimação (interações, uptime, clientes)
- Pensar em uma seção que "mostre" a plataforma antes de descrevê-la
- Criar uma seção de diferenciais com linguagem objetiva (não "somos os melhores")
- Adaptar a lógica de cases/portfolio para mostrar operações reais

## Síntese — Princípios para a InBot Landing

| Princípio | De onde vem | Como aplicar |
|-----------|-------------|--------------|
| Progressão narrativa | Sqala | Cada seção avança a conversa, não repete |
| Uma mensagem por seção | Apple | Headlines curtos, sem ruído |
| Respiro generoso | Apple | Padding vertical 80–128px entre seções |
| Glows e profundidade | Sqala | Radial gradients azuis sutis no fundo |
| Ritmo de densidade | Insany + Sqala | Alternar seções abertas e densas |
| Métricas visíveis | Sqala + Insany | Números de produto como prova de escala |
| Cards funcionais | Sqala | Ícone + título + texto curto |
| Tom preciso | Apple + InBot | Sem exclamações, sem buzzwords |
| Produto antes do discurso | Insany | Mostrar o que a plataforma faz, não prometer |

## Guia Rápido de Decisão

Ao criar qualquer elemento da landing, perguntar:

1. **Sqala diria assim?** (Está assertivo, tecnológico, progressivo?)
2. **Apple aprovaria?** (Tem respiro? A mensagem está limpa? Tem uma coisa só?)
3. **Insany validaria?** (O ritmo está bom? Tem prova de legitimidade?)
4. **A InBot prevalece?** (Está usando as cores, tipografia e tom corretos?)
